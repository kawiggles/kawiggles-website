In the time I have been working with computers, I have developed a number of technical skills, ranging from the basics of computer configuration and troubleshooting to more advanced topics like programming an docker.

Programming

I've been programming consistently since February 2026, which is when I first really dedicated myself to a programming project. However, my experience with programming dates back to when I was in middle school, which is when I first learned syntax. It took many years of understanding how computers work fundamentally before I was able to actually apply the principles of programming in practical projects. Gaining this understanding allowed me to approach programming from an architectural perspective, rather than just worrying about syntax and basic idioms.

My primary interest when it comes to programming are low-level systems tools. I am drawn towards projects which focus on how a system's underlying components function; my database engine, shell, archiver, and http server projects all grew out of a curiosity of how the basic components of the internet function. My projects take on an academic nature as a result: the goal of the project is not necessarily a finished product so much as it is an understanding of the system. Projects which present more complex or interesting academic/engineering challenges are the ones I tend to focus on more, which is why my database engine is my most robust project.

My choice in programming languages also reflects this desire to understand low-level systems. I particularly enjoy using languages which are designed to work with and manipulated binary directly. I have by far the most experience with Rust, which I enjoy because of the type system and inherent safety; I view it as being as less flexible version of C++ that's easier to read, make safe, and actually use because you don't have to choose between paradigms within the language itself. Another language I have a fair amount of experience with is Go, which this website is written in. Go is extremely convenient because of its concurrency model and brevity. Most tasks can be accomplished in only a couple lines of Go, so it's fantastic for when you just want to get a thing done. I don't often choose it for hobby projects because it's pretty boring to write, but first class functions, the channel based/goroutine concurrency model, and the package system on top of being a compiled, typed language with pointers make it easy to work with, especially when compared to Python (type hinting does not help). I have experience in a number of other languages, including C, which was the first language I learned, C++, Python, and Zig, which I really enjoy because it adds modern concepts like errors as types, tagged unions, and explicit allocation to a C-like base.

Systems Administration

My experience with systems administration began when I first setup my homelab. Originally, my homelab was just an excuse to build another computer because I liked building my gaming computer so much. However, as I went through the process of learning how to setup and maintain a server, I came to be familiar with a number of essential systems administration skills

Perhaps chief among these skills is my experience with Linux. The first iteration of my homelab ran a proprietary distribution of Linux called Unraid. This operating system was extremely user friendly, which gave me an easy introduction to topics such as redundant drive arrays, containerization, and basic networking. I learned what docker containers were, how to set up port forwarding and internal networking, configured a basic reverse proxy with a preconfigured container, and exposed parts of my server to the internet with DNS resolution while also securing other services using tailscale's mesh networking. The experience with the OS also gave me the confidence to eventually approach and experiment with actual Linux distributions.

In an effort to improve my skills with Linux, I switched my daily use desktop and laptop over to Arch Linux in February of 2026 so as to force myself to become familiar with the system. This was an extremely rewarding experience that got me comfortable with using package managers, controlling services, using the command line, and troubleshooting problems. It was during this time that I became extremely comfortable with vim (which I use as my main text editor), and learned about the unix philosophy, with a particular focus on Filesystem Hierarchy Standard, the universality of file descriptors, and how configuration is approached broadly on unix systems.

Eventually, Unraid's GUI oriented interface and tools became extremely frustrating to work with, a difficulty that was wholly unnecessary given that I was paying money for the system. So in September of 2026, I migrated my entire homelab infrastructure to Debian Linux. This experience was also extremely rewarding, as it allowed me to practically interact with the systems which I had only used through GUI abstractions previously. For instance, setting up this server allowed be to try using Nginx directly to manage reverse proxies, had me deploy docker containers using docker compose instead of a convenient GUI, and allowed me to build my own RAID arrays using mdadm. The most informative part of this migration was ensuring that data survived the transition. This required me to draft an informal change proposal/plan to ensure that I took the proper precautions when migrating data, including creating backups, running SMART tests, and building arrays in the proper order.
